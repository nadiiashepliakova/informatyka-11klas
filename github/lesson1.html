🖥️ 1. Базові поняття: вебсервер, хостинг і домен

Щоб створений вами вебсайт був доступний в інтернеті для інших користувачів, недостатньо просто написати код на комп'ютері. Необхідні три ключові компоненти:

  • Вебсервер — це потужний комп'ютер, який працює цілодобово, підключений до мережі інтернет і видає сторінки за запитами користувачів.
  • Хостинг — послуга з надання дискового простору та ресурсів сервера для розміщення сайту.
  • Доменне ім'я — унікальна текстова адреса сайту (наприклад, mysite.ua), яка замінює складну IP-адресу сервера.

Побутова аналогія: Хостинг — це орендована квартира (місце, де все зберігається), а домен — це поштова адреса, за якою вас знаходять друзі.

🐙 2. Що таке Git та GitHub?

Git — це розподілена система контролю версій. Вона дозволяє фіксувати зміни в коді, повертатися до попередніх версій та працювати над проєктами командно без ризику втратити дані.

GitHub — це найбільша вебплатформа для хостингу IT-проєктів та спільної розробки на базі Git. Вона забезпечує хмарне зберігання коду та надає інструмент GitHub Pages для безкоштовного хостингу статичних сайтів.

📂 3. Основні терміни GitHub

📦 Репозиторій (Repository)

Папка проєкту на GitHub, де зберігаються всі файли сайту, історія їхніх змін та налаштування.

💾 Коміт (Commit)

Точка збереження стану файлів. Кожен коміт супроводжується коротким описом зроблених змін.

🌿 Гілка (Branch)

Незалежна лінія розробки. Основна робоча гілка зазвичай називається main або master.

🚀 Деплой (Deployment)

Процес публікації сайту на хостингу, після якого він стає доступним усім користувачам інтернету.

⚖️ 4. GitHub Pages: переваги та обмеження

Переваги:

  • Повністю безкоштовно для публічних репозиторіїв.
  • Надійність та висока швидкість завдяки серверам GitHub.
  • Автоматичне підключення безкоштовного SSL-сертифіката (захищений протокол HTTPS).
  • Миттєве оновлення сайту при кожному новому коміті.

Обмеження:

  • Підтримує лише статичні сайти (HTML, CSS, JavaScript). Динамічні мови (PHP, Python, Node.js на сервері) не працюють.
  • Обмеження на обсяг репозиторію та трафік (до 100 ГБ на місяць для безкоштовних акаунтів).
🎯 5. Золоті правила публікації та симулятор URL

Головні правила успішного деплою:

  1. Головна сторінка сайту обов'язково повинна називатися index.html (у нижньому регістрі).
  2. Усі шляхи до зображень, стилів та скриптів мають бути відносними (наприклад, images/photo.jpg, а не повними шляхами з вашого диска).
  3. У налаштуваннях репозиторію (Settings → Pages) джерелом публікації (Source) потрібно обрати гілку main та теку /root (або / (root)).

Практична робота:
Створення та публікація сайту

Виконайте послідовні кроки для створення власної вебсторінки та розміщення її на GitHub Pages.

Крок 1. Підготовка стартового файлу

Створіть на комп'ютері файл з назвою index.html та скопіюйте до нього наступний шаблон:

<!DOCTYPE html>
<html lang="uk">
<head>
    <meta charset="UTF-8">
    <title>Мій перший сайт на GitHub Pages</title>
    <style>
        body { font-family: Arial, sans-serif; text-align: center; padding: 50px; background: #e0f2fe; color: #0369a1; }
        h1 { font-size: 2.5rem; }
        p { font-size: 1.2rem; }
    </style>
</head>
<body>
    <h1>Привіт, світ! 🚀</h1>
    <p>Мій сайт успішно опубліковано на GitHub Pages!</p>
</body>
</html>

Крок 2. Чекліст виконання роботи

Відмічайте виконані етапи для відстеження прогресу:

  • Зареєстровано обліковий запис на GitHub.
  • Створено новий публічний репозиторій (Public Repository).
  • Створено файл index.html з базовою HTML-розміткою.
  • Завантажено (закомічено) файл index.html у головну гілку репозиторію.
  • Увімкнено GitHub Pages у налаштуваннях репозиторію (Settings → Pages).
  • Перевірено роботу сайту за отриманою посиланням-адресою.

Критерії оцінювання практичної роботи:

  • 10–12 балів: Сайт успішно опубліковано, посилання працює, код містить власні модифікації та доповнення.
  • 7–9 балів: Сайт опубліковано за шаблоном, але допущено незначні огріхи у структуруванні файлів.
  • 4–6 балів: Репозиторій створено, але деплой не завершено або файл названо з помилкою.
